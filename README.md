## class101 클론 프로젝트 리드미

> HTML/CSS/JavaScript로 만든 **클래스101 스타일 온라인 클래스 웹사이트** 클론/리디자인 프로젝트입니다.  
> 주니어 프론트엔드 개발자 입장에서, **레이아웃 설계 · 반응형 · UI 디테일 · 간단한 인터랙션**을 집중적으로 연습했습니다.

### 2. 페이지별: 어떤 기능을 중점적으로 공부했는지

#### 2-1. `index.html` – 메인 랜딩 페이지

**역할**
- 서비스 첫 인상을 담당하는 랜딩 페이지.
- **슬라이더, 카테고리 숏컷, 추천 클래스, 베스트, 블로그, Tip & Tech, 얼리버드 카운트다운** 등 실제 상용 서비스 구조를 최대한 비슷하게 구현했습니다.

**중점적으로 연습한 내용**
- **슬라이더(Slick Slider)와 히어로 섹션**
  - `.front-slider-items`에 Slick을 적용해 **자동재생, 반응형 슬라이더** 구현.
  - 활성 슬라이드에만 CSS transition을 걸어, **텍스트/이미지가 자연스럽게 등장하는 효과**를 연습했습니다.
  - 그 과정에서 “슬라이더 플러그인에 종속되지 않고, CSS만으로도 충분히 다이내믹한 느낌을 줄 수 있다”는 감각을 익혔습니다.

- **카테고리 숏컷 + 이미지 아이콘 구조**
  - 처음엔 Bootstrap Icons → Font Awesome → 최종적으로 **이미지 아이콘(icon01~06.png)** 으로 정리했습니다.
  - 실제 회사에서는 디자인 팀에서 넘겨준 아이콘 에셋을 쓰는 경우가 많기 때문에,  
    아이콘 폰트 의존이 아닌 **“이미지 기반 아이콘을 감싸는 공통 레이아웃(em)”** 패턴을 연습하는 목적이었습니다.

- **여러 섹션을 가진 긴 페이지 레이아웃**
  - “강의 그 이상의 배움”, “기초부터 응용까지”, “카테고리 별 베스트”, “블로그”, “Tip & Tech” 등  
    동일한 카드 컴포넌트(`.focus-class-item`)를 **다양한 섹션에서 재사용**하는 구조를 설계했습니다.
  - 이를 통해 “디자인은 달라도, 코드 레벨에서는 같은 레이아웃을 재사용하는 습관”을 들이려고 했습니다.

- **카운트다운 영역 (얼리버드 배너)**
  - 초기: jQuery 기반 카운트다운 플러그인(`jquery.countdown`) 사용.
  - 최종: **순수 자바스크립트 (Date + setInterval)** 로 재구현, `N일 N시간 N분 N초 남음` 포맷을 직접 포맷팅.
  - 플러그인에 의존하지 않고 **날짜 계산/포맷 로직을 손으로 짜보는 연습**이었습니다.

- **Go to Top 버튼 + 스크롤 인터랙션**
  - 푸터에만 존재하는 `.gototop` 버튼을, **이벤트 위임**으로 어느 페이지에서도 쓸 수 있게 변경.
  - 스크롤 위치(700px)를 기준으로 보였다/숨겼다 하는 로직으로, 간단한 스크롤 이벤트 처리 패턴을 익혔습니다.

#### 2-2. `html/category-main.html` – 개발·프로그래밍 카테고리 메인

**역할**
- `개발·프로그래밍` 카테고리의 **대표 클래스 16개를 슬라이더/그리드 형태로 보여주는 목록 페이지**입니다.
- 상단에는 카테고리 대표 이미지, 중간에는 세부 카테고리 버튼, 하단에는 클래스 카드 리스트가 이어집니다.

**중점적으로 연습한 내용**
- **카테고리/태그 버튼 UI**
  - `세부 카테고리` 영역에서 “전체/웹 개발/프론트엔드/백엔드/모바일 앱 개발/데이터베이스/게임 개발/자격증” 버튼을 만들며,  
    **버튼 그룹 내 active 상태 토글 UI**를 jQuery로 구현했습니다.

- **카드 레이아웃 통일 + 도메인 데이터 정리**
  - 초기에는 전부 퍼블리싱/코딩웍스 강의였던 것을,  
    프론트엔드, 백엔드, 데이터, 모바일, AWS, 자격증, 커리어 등으로 **강의 제목/멘토/강의 수/시간을 다시 설계**했습니다.
  - 이렇게 하면서 “같은 컴포넌트라도 도메인 데이터에 따라 완전히 다른 느낌을 줄 수 있다”는 걸 체험했습니다.

- **정렬/필터 시도와 되돌리기**
  - 한 번은 평점순/가격순/할인 필터를 jQuery로 직접 구현하려다가, Slick 슬라이더 레이아웃과 충돌하는 문제가 생겼습니다.
  - 결국 정렬 기능은 과감하게 빼고, **페이지의 본질(카드 목록 뷰)을 망가뜨리지 않는 선**에서 필터만 부분적으로 사용해 보는 등  
    “무조건 기능을 많이 넣는 것보다, 레이아웃 안정성이 더 중요하다”는 트레이드오프를 경험했습니다.

#### 2-3. `html/class-detail.html` – 클래스 상세 페이지

**역할**
- 한 개 클래스의 **상세 설명/커리큘럼/수강 후기/FAQ/멘토 정보를 모두 담는 페이지**입니다.
- 좌측은 상세 정보, 우측은 결제 관련 사이드바 구조로 이루어진 전형적인 강의 상세/상품 상세 페이지 구조입니다.

**중점적으로 연습한 내용**
- **히어로 배너 리디자인 (이미지 → 텍스트 배너)**
  - 처음에는 큰 이미지를 배경으로 갖는 섹션이었지만, 이후에 이미지 없이 **컬러 + 타이포그래피만 있는 배너**로 바꿨습니다.
  - 그라디언트 대신 단색 배경(`var(--color-brand-indigo)`)을 사용해서  
    “주니어에게 흔한 과한 그라디언트 사용”을 지양하고, **깔끔한 한 줄 배너**에 집중했습니다.

- **클래스 정보 정리**
  - “성공/루틴/습관/목표”라는 주제에 맞게 클래스 소개, 강의주제, 자료제공 섹션의 텍스트를 전부 리라이팅했습니다.
  - 퍼블리셔 예제 텍스트가 아니라 **실제 교육 서비스에 올려도 어색하지 않을 정도의 카피**를 쓰려 노력했습니다.

- **커리큘럼 아코디언**
  - 각 챕터를 `.chapter-title`/`.chapter-content` 구조로 나누고, jQuery로 **접기/펼치기 토글**과  
    “전체 접기/전체 펼치기” 버튼을 구현해 보았습니다.

- **수강 후기/FAQ/멘토 소개**
  - 후기는 닉네임, 날짜, 별점, 한 줄 코멘트로 구성해 “진짜 유저 후기 같은” 데이터를 넣으려고 했고,  
  - FAQ는 실제로 많이 물어볼만한 질문(시간 부족/준비물/수준 차이)을 가정해서 작성했습니다.

#### 2-4. `html/take-course.html` – 수강신청 장바구니/결제 요약

**역할**
- 내가 담은 강의 목록을 확인하고, **전체 선택/개별 삭제/모두 삭제/결제 금액 요약/휴대폰 인증/약관 동의**까지  
  실제 결제 직전 플로우를 연습하기 위한 페이지입니다.

**중점적으로 연습한 내용**
- **체크박스 & 장바구니 상태 처리**
  - 각 장바구니 아이템에 삭제 버튼(`.btn-clear`)을 두고, 클릭 시 DOM에서 제거합니다.
  - 모든 아이템이 제거되면 “수강바구니가 비었습니다” 영역과 “강의 목록 보기” 버튼이 보이도록 해서,  
    **비어 있는 상태(empty state) UX**를 경험해 보았습니다.

- **금액 요약 박스 레이아웃**
  - 오른쪽 사이드에 “총 결제 금액 / 상품금액 / 총 할인 금액” 블록을 배치해,  
    추후 실제 결제로직을 연결할 수 있는 **시각적 토대를 먼저 마련**했습니다.

#### 2-5. `html/member-register.html` – 회원가입 페이지

**역할**
- 이메일, 비밀번호, 비밀번호 확인, 약관/마케팅 동의를 담은 **단일 스텝 회원가입 폼**입니다.

**중점적으로 연습한 내용**
- **비밀번호 보기 토글**
  - `.toggle-pw` 아이콘을 눌렀을 때 형제 input의 `type`을 `password ↔ text`로 변경하는 로직으로,  
    **여러 개의 비밀번호 필드에 공통 기능을 적용**하는 방법을 연습했습니다.

- **카피와 UX 문구**
  - 상단 문구를 “나를 성장시키는 배움, class101에서 시작하세요.”로 바꾸고,  
  - “할인 혜택 및 마케팅 정보 수신 동의” 텍스트를 넣어서 실제 서비스와 비슷한 가입 UX를 만들어 봤습니다.

#### 2-6. 공통 컴포넌트 & 자바스크립트 (`include/`, `script/custom.js`)

**공통 헤더/푸터**
- `include/header.html` / `include/footer.html` 를 `$('.header-include').load('/include/header.html')` 방식으로 불러와서  
  **페이지별로 중복되지 않는 공통 레이아웃 구조**를 만들어 보았습니다.

- 푸터에는 연락처/고객센터/지식공유자 메뉴와 함께 **SNS 아이콘, 회사 정보, Go to Top 버튼**이 있습니다.

**`script/custom.js`에서 연습한 것들**
- 헤더 내 **로그인 모달 열기/닫기**, 로그인 이후 헤더 상태 전환
- 카테고리 버튼/FAQ/커리큘럼 아코디언 등의 **클릭 기반 토글 인터랙션**
- 메인 슬라이더/포커스 클래스 슬라이더 초기화
- Go to Top, 카운트다운, 카트 확인 토스트 등 **작은 인터랙션 모음**

### 3. 사용 기술 스택

- **HTML5/CSS3**
  - 시맨틱 태그, BEM-ish 클래스 네이밍(완전 BEM은 아니지만 역할별로 잘 나누려고 노력)
  - Flexbox 중심 레이아웃, `object-fit`, 반응형 미디어쿼리

- **JavaScript**
  - ES5/ES6 혼용, 순수 JS + jQuery 둘 다 사용해보며 차이를 느끼는 연습
  - `setInterval`, `Date` 객체를 활용한 카운트다운 구현
  - DOM 조작(append, show/hide, class 토글) 패턴

- **jQuery**
  - 기존 템플릿이 jQuery 기반이라 이를 이어받아서 헤더/모달/아코디언 등을 구현

- **외부 라이브러리**
  - Slick Slider (메인/클래스 슬라이더)
  - 초기에는 The Final Countdown 플러그인 사용, 이후 순수 JS로 대체

### 4. 전체 회고 (주니어 개발자 입장에서)

1. **“디자인 예제”에서 “서비스 비슷한 것”으로**
   - 처음 이 프로젝트를 시작했을 때는 단순히 퍼블리싱 예제를 따라치는 느낌이 강했습니다.  
   - 하지만 중간부터 **텍스트·강의명·카테고리·멘토 이름을 전부 리디자인**하면서,  
     “이걸 진짜 서비스라고 생각하고 만들면 어떤 카피를 넣고 어떤 구조를 가져가야 할까?”를 자연스럽게 고민하게 되었습니다.
   - 그 결과, 똑같은 HTML 구조라 하더라도 **텍스트와 데이터가 바뀌면 페이지가 주는 인상이 완전히 달라진다**는 걸 체감했습니다.

2. **기능 추가보다 레이아웃 안정성이 먼저**
   - category-main에 정렬/필터 기능을 욕심내서 구현하다가, 슬라이더와 충돌하면서 레이아웃을 망가뜨린 경험이 있습니다.  
   - 이 과정을 통해 “새로운 기능을 넣는 것보다, 이미 잘 돌아가는 레이아웃과 UX를 깨지 않는 것이 훨씬 중요하다”는 걸 배웠습니다.
   - 이후에는 **작은 필터(할인 여부 정도)부터, 레이아웃을 깨지 않는 선에서만 적용**하려고 의식적으로 조절했습니다.

3. **변수와 공통 컴포넌트의 필요성**
   - 프로젝트 초반에는 색상과 폰트 크기가 여기저기 하드코딩되어 있어서, 색을 한 번 바꾸려면 여러 군데를 찾아다녀야 했습니다.  
   - 중간에 `:root` 색상 변수를 정리하고, 공통 컴포넌트(카드/헤더/푸터)를 인지하면서 **스타일 변경 비용이 크게 줄어드는 경험**을 했습니다.
   - 나중에 React/Next 환경에서 작업할 때는 이 경험을 살려 **테마 시스템이나 디자인 시스템 컴포넌트를 도입**하고 싶다는 생각을 했습니다.

4. **플러그인에 의존하지 않는 연습**
   - 카운트다운처럼 간단한 기능도 처음에는 플러그인에 의존했지만,  
     직접 Date 계산 로직을 짜보면서 브라우저에서 시간이 어떻게 계산되는지 이해도가 높아졌습니다.
   - 슬라이더를 완전히 직접 만들기는 아직 부담되지만, **필요한 최소한만 플러그인을 쓰고 나머지는 직접 구현해 보는 습관**을 들이고 싶습니다.

5. **다음에 개선하고 싶은 점**
   - 지금은 정적인 HTML 기반이라, **반복되는 카드/섹션을 템플릿화하기 어렵고 유지보수 비용이 큽니다.**  
   - 이후에는 React 혹은 Vue로 옮겨서:
     - 카드/배너/섹션을 컴포넌트 단위로 나누고
     - JSON 데이터로 강의/카테고리를 관리하며
     - 정렬/필터를 상태 기반으로 다시 설계해 보고 싶습니다.
   - 또, 실제 API가 없더라도 **mock API + fetch 패턴**을 도입해 “실제 서비스에 더 가까운 데이터 흐름”을 연습해 볼 계획입니다.
